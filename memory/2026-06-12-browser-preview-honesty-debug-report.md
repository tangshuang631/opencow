# DEBUG REPORT

- Symptom: browser preview mode still returned success-shaped local project run, stop, screenshot, and showcase results, which made the desktop assistant look like it had really executed host-side work when it had only produced static preview data.
- Root cause: `apps/desktop/src/features/assistant/localAssistantService.ts` used browser-preview fallback constructors that populated runtime-like fields such as `pid`, `running`, and artifact/write summaries even when `hasTauriInvoke()` was false. `apps/desktop/src/features/assistant/assistantTaskService.ts` then surfaced those fields as if they were execution results.
- Fix: added `preview_only` markers to the affected result types in [localAssistantService.ts](E:/2026/opencow/apps/desktop/src/features/assistant/localAssistantService.ts), changed browser-preview fallback summaries/stdout to explicitly say "did not execute" / "readonly preview", and taught [assistantTaskService.ts](E:/2026/opencow/apps/desktop/src/features/assistant/assistantTaskService.ts) to render preview-only project run/stop/NPC summaries without implying real host execution.
