# 07. 桌面工作台 UI

## 1. 技术路线

- `Tauri + React + TypeScript`
- `assistant-ui` 作为聊天交互骨架
- 参考 `cdesktop` 的会话区、计划区、预览区、工具区信息架构
- 桌面端是主目标，Web 预览只用于开发调试和快速查看。

## 2. 视觉方向

必须白色浅色为主。

参考气质：

- Codex 的侧边栏和工作流清晰度。
- 文心一言、豆包的简洁对话体验。
- cdesktop 的工作台信息架构。

避免：

- 过暗。
- 过重。
- 过多卡片。
- 拥挤后台风。
- 花哨渐变。
- 首页堆满设置。

## 2.1 Figma 重构优化入口

前端必须保留后续用 Figma 重构和优化的入口。

- 组件命名要稳定，方便和 Figma 图层、组件、变量映射。
- 颜色、间距、圆角、字体尽量集中在样式变量或明确样式层中。
- 工作台布局要保持模块化，方便未来按 Figma 设计稿替换局部区域。
- 不把视觉决策写进业务逻辑。
- 后续如果提供 Figma 文件或节点，应优先按 `figma-implement-design` 工作流进行桌面端实现。
- Figma 优化后的验收仍以 Tauri 桌面端为准。

## 3. 布局

```text
Left Sidebar | Main Conversation | Right Inspector
              Bottom Composer
```

左侧：

- 新对话。
- 搜索。
- 知识库。
- Skills。
- NPC。
- MCP。
- 审计。
- 设置。

中间：

- 会话流。
- 工具调用状态。
- 计划步骤。
- 错误和修复提示。
- 会话流中同时容纳欢迎消息、系统事件、最近操作和直接回退入口。

底部：

- 输入框。
- 附件。
- 当前模型。
- 当前权限。
- 联网搜索开关状态。
- 发送/停止。

右侧：

- 输出产物。
- 来源。
- 工具结果。
- 日志摘要。
- 回退记录。

## 4. 回退交互

- 用户每条消息旁边显示回退按钮。
- 默认展示为低干扰图标。
- hover 显示说明。
- 点击后弹出确认面板。
- 确认后回退到该消息执行操作前状态。
- 在纯原型阶段，尚未接入真实用户消息时，可先用系统事件卡片承载相同回退入口，但后续要平滑替换到真实消息旁。

## 5. 错误交互

错误不能只显示“失败”。

必须显示：

- 错误摘要。
- 发生模块。
- 查看详细日志入口。
- 可尝试修复入口。
- 是否可以重试。
