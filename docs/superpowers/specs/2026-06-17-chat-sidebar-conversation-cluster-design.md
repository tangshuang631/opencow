# Chat Sidebar Conversation Cluster Design

## Goal

重做网页端与共享工作台中的“会话区”侧边栏结构，让它更像真实聊天产品，而不是把：

- `会话`
- `新对话`
- `最近会话`

拆成三个彼此独立的入口。

本次只重做“会话区”这一段，不改下面的：

- `搜索`
- `知识库`
- `Skills`
- `NPC`
- `MCP`
- `审计`
- `安全`
- `设置`

## Desired User Experience

用户进入页面后：

- 左侧顶部仍然看到 `会话`
- 左侧顶部的 `会话总卡片` 右侧同时看到 `放大镜` 与 `加号` 图标
- `会话` 下方直接看到最近 `3` 个会话卡片
- 点击展开后最多看到最近 `6` 个会话卡片
- 点击某个会话卡片主体，直接进入该会话并查看历史消息
- 点击某条会话右侧的小减号，删除该会话及其对应聊天记录
- `放大镜` 图标，用于展开“搜索历史会话”输入框
- `加号` 图标，用于创建新会话

这次设计不再保留独立的：

- `新对话` 侧边栏按钮
- `最近会话` 侧边栏按钮

## Why This Change

当前问题：

- `会话`、`新对话`、`最近会话` 被拆成多个导航入口，信息架构像功能台，不像聊天产品
- 用户要“继续聊”“切历史”“新建会话”时，操作路径太散
- 最近会话虽然已经有保留逻辑，但入口位置不自然，和会话本身割裂

目标状态：

- “会话”成为一个包含当前会话切换、历史预览、删除、检索、新建的统一模块
- 会话相关动作集中到一个区域里完成
- 历史会话默认轻量展示，但仍能快速展开与检索

## Approaches Considered

### 1. 会话分组折叠列表 `(Recommended)`

左侧保留一个 `会话` 组标题，组内默认显示最近 `3` 条，展开显示最近 `6` 条；新建与检索移到白色主内容区顶部右侧图标。

Pros:

- 最贴近用户要求
- 最符合聊天产品的常见结构
- 改动集中在“会话区”，不会误伤下方能力导航

Cons:

- 需要重组当前 `Sidebar`、`MainConversation`、`Workbench` 的会话入口职责

### 2. 会话分组 + 独立历史面板

左侧只保留少量会话摘要，更多历史由白色区域切到单独检索面板。

Pros:

- 左侧更简洁

Cons:

- 不符合“默认 3 条、展开 6 条”的目标
- 历史切换会多一次视图跳转

### 3. 固定 6 条最近会话

不做折叠，始终显示最近 `6` 条会话。

Pros:

- 实现最简单

Cons:

- 不符合默认只显示 `3` 条的要求
- 小屏下会明显挤压下方能力导航

## Chosen Design

采用 `方案 1：会话分组折叠列表`。

### Left Sidebar Scope

左侧顶部区域从：

- `会话`
- `新对话`
- `最近会话`

改为一个统一的 `会话分组`。

分组包含：

- 会话标题行
- 最近会话列表
- 折叠/展开控制

下面的能力导航分组保持原有顺序和入口，不在本次改造范围内。

## Interaction Design

### 1. 会话标题行

标题行为 `会话`，始终固定在左侧顶部。

标题行职责：

- 表示当前处于会话模块
- 作为“会话总卡片”的左侧标题区域
- 提供“展开/收起最近会话列表”的交互入口
- 在同一行右侧承载：
  - `放大镜`
  - `加号`

默认状态：

- 只展示最近 `3` 个会话卡片

展开状态：

- 展示最近 `6` 个会话卡片

如果最近会话不足目标数量：

- 按实际数量显示

### 2. 会话卡片

每个会话卡片包含：

- 会话标题
- 简短摘要
- 右侧删除按钮

行为：

- 点击卡片主体：恢复并切换到该历史会话
- 点击右侧小减号：删除该会话及对应聊天记录

删除按钮要求：

- 小尺寸
- 视觉上靠右
- 优先显示为减号而不是完整文本按钮

### 3. 会话总卡片右侧动作

在左侧顶部的 `会话总卡片` 右侧增加两个图标按钮：

- `放大镜`
- `加号`

`放大镜` 行为：

- 点击后在左侧会话列表顶部展开一个“搜索历史会话”输入框
- 输入时按 `title + summary` 对所有已保留的最近会话进行前端过滤
- 搜索是列表内筛选，不切换到单独页面

`加号` 行为：

- 创建新会话
- 立即切换到空白新会话
- 左侧会话分组继续保留最近会话列表

### 4. 搜索行为边界

本次搜索只覆盖：

- 当前已保存的全部最近会话记录，而不是只筛可见的 `3` 或 `6` 条

不包含：

- 远程检索
- 全量数据库分页
- 当前会话正文内全文搜索

如果筛选无结果：

- 在会话列表区域显示空结果提示
- 不影响已有会话数据

## State And Data Design

### Existing State To Reuse

优先复用当前已有的：

- `state.history.recentConversations`
- `onNewConversation`
- `onRestoreRecentConversation`
- `onDeleteRecentConversation`

这次改造的重点是：

- 重构展示方式
- 调整触发入口

而不是重写会话持久化协议。

### New Local UI State

建议新增轻量 UI state：

- `isConversationClusterExpanded`
- `conversationSearchQuery`

它们只影响界面展示，不改底层会话数据结构。

推荐规则：

- 默认 `isConversationClusterExpanded = false`
- 点击会话标题行后切换展开状态
- `conversationSearchQuery` 非空时，对最近会话列表做过滤

### Delete Behavior

删除某个最近会话时：

- 同时删除该最近会话记录
- 同时移除对应聊天记录

若删除的是当前正在查看的会话：

- 优先切换到剩余列表中的最近一条
- 若已无剩余会话，则切到空白新会话

## Layout Responsibilities

### Sidebar

`Sidebar` 不再承担：

- 独立 `新对话` 按钮
- 独立 `最近会话` 按钮

`Sidebar` 改为承担：

- 会话分组入口
- 会话列表显示
- 会话删除按钮
- 会话折叠状态展示

### Workbench

`Workbench` 负责：

- 持有会话分组展开状态与搜索词
- 把恢复、删除、新建等 handler 下发给侧边栏会话总卡片
- 驱动会话总卡片右侧 `搜索 / 新建` 图标动作

### Main Conversation

`MainConversation` 不再承担“空白会话时显示最近会话面板”的主入口职责。

最近会话主入口前移到左侧会话分组。

`MainConversation` 仍负责：

- 当前会话消息展示
- 长输入折叠
- 知识命中卡片
- 回退按钮

必要时可以保留极简空白态提示，但不再重复渲染完整最近会话列表。

## Accessibility

需要保证：

- 会话标题行可键盘操作
- 折叠状态有明确 `aria-expanded`
- 删除按钮有明确 `aria-label`
- 搜索输入框有明确标签，如 `搜索历史会话`
- 恢复历史会话时焦点与选中态可感知

## Testing Strategy

至少补齐以下测试：

1. 左侧不再出现独立 `新对话`
2. 左侧不再出现独立 `最近会话`
3. 会话分组默认只显示最近 `3` 条
4. 展开后显示最近 `6` 条
5. 点击会话卡片主体可恢复对应历史
6. 点击会话卡片删除按钮可删除对应会话
7. 删除当前会话时，自动切到剩余最近一条或空白新会话
8. 点击白色区域顶部 `+` 可新建会话
9. 点击左侧会话总卡片右侧 `+` 可新建会话
10. 点击左侧会话总卡片右侧放大镜后展开搜索框
11. 输入搜索词后，只过滤最近会话列表，不影响底层持久化

## Out Of Scope

本次不包含：

- 下方 `知识库 / Skills / NPC / MCP / 审计 / 安全 / 设置` 导航重排
- 历史会话无限滚动
- 历史会话跨设备同步
- 当前消息正文全文检索
- 会话重命名
- 会话拖拽排序

## Implementation Notes

建议按以下顺序实施：

1. 先重构 `Sidebar` 结构与文案
2. 再把 `Workbench` 中会话相关入口合并
3. 再调整 `MainConversation` 的空白态最近会话逻辑
4. 最后统一改测试和样式

这样可以避免：

- 先改样式后改结构导致测试大面积失真
- 同时改入口与持久化，导致历史记录行为难以定位
