## 1. 项目定位

### 1.1 项目名称
`opencow`

### 1.2 项目愿景
opencow 是一个面向国内用户的本地优先桌面 AI 助手。它以 `openclaw` 的后端能力为基础做减法和重构，目标不是做一个功能堆叠的大而全平台，而是做一个更安全、更轻量、更迅捷、更放心的本地助手。

它的核心价值是：

- 默认优先使用本地 `Ollama`
- 尽量保留 `openclaw` 的能力上限
- 显著提高默认下限，让常见任务更稳定、更省 token、更少配置
- 将敏感操作放在明确权限边界内执行
- 让用户能看清系统做了什么、为什么做、是否可回退

### 1.3 产品关键词

- 本地优先
- Ollama 优先
- 桌面端优先
- 中文优先
- 安全可控
- 可提权
- 可审计
- 可回退
- 低配置
- 轻量迅捷

## 2. v1.0 产品目标

### 2.1 v1.0 核心目标
v1.0 交付的是一套可实际使用的本地桌面助手底座，而不是完整的生态平台。

必须做到：

- 基于 `openclaw` 后端能力进行桌面化改造
- 功能能力不低于当前目标保留范围，重点做体验简化与效率提升，而不是能力阉割
- 默认优先接入本地 `Ollama`，自动读取本地模型列表
- 首页仅强调本地模型与本地助手路径
- 保留 `baseUrl + apiKey` 外部模型接入能力，但折叠到高级设置
- 采用浅色、简洁、低干扰的桌面工作台界面
- 让敏感操作基于当前权限模式决定是否执行
- 权限不足时明确提示用户，并允许用户主动提权
- 建立文件快照、审计日志、任务日志、工具日志、权限日志
- 默认优先“预览、快照、副本写入、确认执行、必要时回退”
- 保证启动速度、首屏速度、常见任务响应速度优先

### 2.2 v1.0 明确不做

- 不做复杂插件市场
- 不做云端账号体系
- 不做多端同步
- 不做企业级多租户权限系统
- 不做默认高权限自动执行
- 不做首页暴露复杂模型接入配置
- 不做过重的 web-first 形态

## 3. 目标用户与使用场景

### 3.1 目标用户

- 希望以较低成本使用本地模型的个人用户
- 需要安全、可控、可回退 AI 助手的开发者和办公用户
- 希望减少复杂配置流程、尽量开箱即用的国内用户
- 需要处理资料整理、搜索、总结、改写、文件产物生成等任务的高频用户

### 3.2 典型场景

- 读取本地资料并整理摘要、报告、表格、文案
- 结合联网搜索与本地资料完成问答和整理
- 处理截图、PDF、Word、代码文件等输入
- 在工作区内生成、修改、导出文档产物
- 在明确权限范围内执行文件整理、重命名、归类等任务
- 对失败任务进行诊断、重试、受控修复

## 4. 核心产品原则

### 4.1 本地优先
默认走本地 `Ollama`。模型列表、聊天推理、Embedding、日志、配置、缓存尽量本地化，尽量减少对外部服务的依赖。

### 4.2 Ollama 优先但不锁死
Ollama 是默认入口，不代表只能使用 Ollama。

v1.0 规则：

- 首页只展示 Ollama 接入与本地模型状态
- 外部模型接入收纳到“高级设置”
- 支持 `baseUrl + apiKey` 的通用兼容接入
- 支持与 `ccswitch` 一类模型切换工具配合
- 默认任务编排、模型枚举、健康检查优先按 Ollama 设计

### 4.3 安全优先
敏感操作不应以“模型觉得可以做”为依据，而应以“当前权限是否允许、用户是否明确同意”为依据。

### 4.4 权限驱动执行
任何文件写入、覆盖、删除、批量改动、外部调用、系统级操作，都必须先通过权限判定。

如果权限不足：

- 不静默失败
- 不擅自绕过
- 必须向用户说明原因
- 明确展示需要的权限级别
- 允许用户主动提权后重试

### 4.5 可审计
用户必须能看见模型调用、工具调用、搜索来源、文件访问、权限变更、敏感确认、回退记录。

### 4.6 可回退
高风险变更优先走快照、副本、差异预览。无法保障回退能力时，默认拒绝自动执行，只输出方案与风险说明。

### 4.7 轻量迅捷
v1.0 优先做轻快体验：

- 安装少步骤
- 首次配置少步骤
- 启动更快
- 空间占用更轻
- 常见任务路径更短
- 上下文更克制，尽量节省 token

### 4.8 中文优先与 UTF-8 优先
opencow 是中文优先项目。所有新增源码、脚本、配置、文档默认必须使用 `UTF-8` 编码，避免开发和运行阶段反复出现乱码问题。

规则：

- 新增文件默认使用 `UTF-8`
- 中文文案、日志、错误提示、说明文档统一按 `UTF-8` 开发
- Windows 开发脚本优先显式设置 `UTF-8` 终端环境
- 不允许在未确认编码影响范围时批量改写已有文件编码
- 构建链路、日志链路、导入导出链路都要把编码兼容作为必测项

### 4.9 谨慎编码与分块编码
opencow 不追求把大量逻辑堆进单个大文件，而是要求在可维护性、可调试性、可替换性上优先。

规则：

- 按模块拆分文件，避免“大一统文件”
- 单个文件达到一定复杂度后必须继续拆分
- 优先让每个模块只承担一个清晰职责
- 目录结构应服务于调试、替换、性能优化和后续重构
- 核心模块之间通过明确接口通信，减少隐式耦合

## 5. 产品形态与界面原则

### 5.1 桌面端优先
opencow 是桌面端优先项目，当前主线以 Windows 和 macOS 桌面应用为准。

推荐技术路线：

- `Tauri + React + TypeScript`

原因：

- 包体更小
- 启动更快
- 更适合做本地权限与安全边界
- 更适合国内分发
- 更符合本地助手定位

当前开发约束：

- 后续功能开发、交互修复、验收回归优先落在 `apps/desktop`
- Windows 和 macOS 桌面端共享同一条正式交付主线
- `apps/web` 当前只保留已有调试与回归基线，不继续扩展新功能
- 当桌面端主线稳定后，再统一把必要能力回补到 web 端，避免桌面/web 双线分叉

### 5.2 前端路线
推荐主路线：

- `assistant-ui + Tauri` 自组桌面端

推荐借鉴：

- 参考 `cdesktop` 的信息架构

结论：

- 不直接照搬 `cdesktop`
- 借它的工作台布局思路
- 用 `assistant-ui` 作为对话交互骨架
- 用 Tauri 构建真正的桌面端壳

### 5.3 视觉风格
风格参考 `Codex / 文心一言 / 豆包` 的简洁工作台气质，但不照抄。

界面原则：

- 浅色、白色为主、低干扰
- 留白充足，但信息层级明确
- 左侧轻导航
- 中间主工作区
- 底部输入区固定
- 右侧折叠结果/来源/工具/日志面板
- 设置入口后置
- 首页先能用，复杂能力折叠
- 美观但克制，不走花哨、厚重、拥挤路线
- 视觉上优先接近参考图和工作台式极简产品

## 6. 总体架构

### 6.1 主架构路线
采用“`openclaw` 后端能力保留 + 新桌面前端 + 新权限安全外壳”的三层结构。

#### A. Desktop Shell
负责：

- 桌面窗口与应用壳
- 导航、会话、结果面板、设置面板
- 文件拖拽、粘贴、目录选择
- 用户确认、提权确认、风险提示
- 日志查看、快照回退入口

#### B. Local Runtime Adapter
负责：

- 对接 `openclaw` 核心运行时
- 统一模型调用入口
- 统一工具调用入口
- 权限校验与执行前拦截
- 上下文压缩和 token 节流
- 任务状态机与失败重试

#### C. Local Storage And Audit
负责：

- 会话数据
- 用户设置
- 权限授权记录
- 审计日志
- 文件快照与回退元数据
- 本地缓存
- 知识库索引

### 6.2 模块划分

1. `desktop-app`
- Tauri 桌面壳
- 原生菜单
- 系统托盘
- 原生目录/文件选择

2. `ui-workbench`
- 应用布局
- 左侧导航
- 主会话区
- 右侧详情面板
- 底部输入区

3. `chat-runtime`
- 会话编排
- 流式输出
- 中断与重试
- 多轮上下文管理

4. `model-gateway`
- Ollama provider
- OpenAI-compatible provider
- 模型枚举
- 健康检查

5. `permission-engine`
- 权限模式判断
- 操作风险分级
- 提权申请
- 授权记录

6. `safety-engine`
- 写入前预览
- 快照创建
- 回退执行
- 高风险确认

7. `tool-runtime`
- 文件读取工具
- 文件写入工具
- 搜索工具
- 产物生成工具
- 后续开放更多本地工具

8. `audit-center`
- 任务日志
- 工具日志
- 权限日志
- 搜索来源日志
- 回退日志

9. `knowledge-service`
- 知识库导入
- 索引构建
- Embedding
- 检索

10. `settings-center`
- Ollama 配置

- 搜索配置

## 7. 模型接入设计

### 7.1 默认模型策略
默认模型策略是 `Ollama-first`。

v1.0 要求：

- 自动检测本机 Ollama 是否可用
- 自动读取本地模型列表
- 默认聊天模型从本地列表中选择
- 默认 Embedding 也优先走本地 Ollama
- 模型不可用时给出明确状态与修复建议

### 7.2 保留 Ollama 优势
opencow 需要保留 Ollama 的主要优点：

- 本地推理
- 成本低
- 响应快
- 模型切换直接
- 列表读取简单
- 本地隐私更可控
- 更适合国内网络环境

### 7.3 高级模型设置
非本地模型能力折叠到高级设置中：

- `baseUrl`
- `apiKey`
- `model`
- `provider label`
- 超时
- 重试
- 并发限制

兼容目标：

- OpenAI-compatible API
- 本地代理
- `ccswitch` 一类模型切换中间层

## 8. 权限系统设计

### 8.1 权限原则
权限不是装饰 UI，而是执行前的硬边界。

### 8.2 建议权限模式

1. `只读`
- 可读取已授权目录
- 可读取附件
- 不允许写入

2. `工作区读写`
- 可读取已授权目录
- 可在用户指定工作区内创建和修改文件
- 不允许危险删除和跨目录大范围改动

3. `受控完全访问`
- 可在用户明确授权范围内执行更高权限操作
- 仍然保留敏感确认和审计

### 8.3 敏感操作规则
以下操作默认视为敏感操作：

- 删除文件
- 覆盖原文件
- 批量重命名
- 批量移动
- 跨目录修改
- 写入系统敏感路径
- 触发外部命令执行

处理规则：

- 先判断权限
- 权限不足则停止执行
- 明确告诉用户“当前权限不足”
- 明确告诉用户“需要哪一级权限”
- 给出“提权并重试”入口
- 用户不提权则只输出建议，不执行操作

### 8.4 目录授权机制

- 用户显式选择可访问目录
- 优先通过原生目录选择器授权
- 不允许模型自行推断整盘权限
- 每个目录授权至少区分“只读”与“读写”

## 9. 安全与回退设计

### 9.1 安全目标
让用户对本地助手更放心，而不是更紧张。

### 9.2 默认安全策略

- 默认低权限
- 默认记录日志
- 默认高风险操作需确认
- 默认优先快照
- 默认优先副本写入
- 默认优先差异预览

### 9.3 文件改动策略
对文件写入类操作，v1.0 优先采用：

- 先生成预览
- 可行时先生成副本
- 必要时创建快照
- 用户确认后再落盘

### 9.4 回退能力
必须建设：

- 文件改动前快照记录
- 任务级回退记录
- 是否已回退状态
- 回退失败原因

如果当前场景无法保证回退：

- 默认不自动执行真实破坏性操作
- 只给出执行方案和风险说明

## 11. 性能与迅捷策略

### 11.1 迅捷目标

- 启动快
- 首屏快
- 首次可用路径短
- 常见任务响应更快
- 减少空转等待

### 11.2 具体策略

- 默认只加载高频功能
- 设置页与审计页延迟加载
- 会话主链路优先
- 工具结果增量展示
- 搜索结果摘要注入而非原文全塞
- 上下文压缩优先在本地完成
- 对低价值冗余上下文做节流

### 11.3 节省 token 策略

- 优先使用本地模型总结上下文
- 工具结果做结构化摘要
- 搜索结果限制注入上限
- 附件抽取后保留摘要与引用
- 长会话启用上下文压缩

## 16. 开发规范

### 16.1 编码规范

- 所有新增文件默认使用 `UTF-8`
- 中文项目文案、日志、脚本、配置必须以 `UTF-8` 为第一约束
- Windows 开发脚本需要显式考虑终端编码与控制台输出编码
- 涉及文本导入导出时，优先提供编码容错或明确错误提示

### 16.2 文件拆分规范

- 新增模块优先分块实现，不写超大核心文件
- 单个文件建议优先控制在便于快速理解和调试的范围内
- 当文件接近 `300-500` 行且职责开始混杂时，应主动继续拆分
- 页面布局、状态管理、权限判断、日志处理、工具执行、模型适配应尽量分文件
- 如需写较复杂逻辑，优先拆成 `view / state / service / types` 之类的结构

### 16.3 架构规范

- 以“功能不降级，体验更简洁高效”为改造目标
- 不是删除 openclaw 的核心能力，而是重组入口、压缩冗余路径、优化默认流程
- 安全、权限、日志、回退相关逻辑必须独立建层，不允许散落在 UI 事件里
- 复杂能力默认折叠到高级区，但后端能力接口要保留扩展空间

### 16.4 UI 规范

- 浅色白色为主
- 默认低干扰，不堆满控件
- 首页优先单一主任务入口
- 高级设置、外部模型、扩展能力后置
- 视觉目标接近参考图中的简约工作台，而不是传统拥挤后台风格

## 17. v1.0 迭代顺序建议

### 第一阶段：底座可跑

- 克隆并梳理 `openclaw`
- 搭建 `Tauri + assistant-ui` 桌面壳
- 打通 Ollama 检测、模型列表、基础聊天

### 第二阶段：安全与权限

- 接入权限模式
- 敏感操作拦截
- 提权交互
- 基础审计日志
- 文件快照与回退元数据

### 第三阶段：工作台能力

- 右侧结果/来源/日志面板
- 文件附件
- 搜索与知识库
- 产物生成与预览

### 第四阶段：优化

- 上下文压缩
- token 节流
- 启动性能优化
- 常见任务模板
- 受控修复与失败诊断

## 18. 开发与验收重点

v1.0 验收重点不是“功能数量”，而是以下四件事是否成立：

- 权限边界是否明确
- 安全与回退是否可信
- 日志与审计是否完整
- 桌面端是否足够轻快顺手
- UTF-8 中文链路是否稳定
- 模块拆分是否清晰、是否避免了超大文件维护风险

## 19. 当前推荐主线结论

opencow v1.0 推荐主线为：

- 后端基础：`openclaw`
- 桌面端：`Tauri`
- 对话骨架：`assistant-ui`
- 信息架构参考：`cdesktop`
- 默认模型入口：`Ollama`
- 外部模型入口：高级设置中的 `baseUrl + apiKey`
- 核心差异化：权限、安全、日志、回退、轻量迅捷

这条路线的目标不是做一个更复杂的 openclaw，而是做一个更适合本地助手场景、默认更稳、更快、更省心的 `openclaw-opencow`。

## 核心开发守则

后续开发必须优先遵循：

- [OPENCOW_CORE_RULES.md](../OPENCOW_CORE_RULES.md)

编码规则以根目录核心守则为准：opencow 自有新增文件优先保持统一编码；接入或修改上游 `openclaw` 文件时优先匹配上游编码与风格；终端和开发脚本遇到中文编码风险时允许使用英文输出；前端用户界面保持中文优先。
